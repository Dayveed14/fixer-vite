# Fixer frontend — changes (18 Oct 2026)

Deploy together with the matching backend (the payment flow changed on
both sides). Env vars: see `.env.example`.

## Central API client (`src/api/`)
- `client.js` — one axios instance: base URL from `VITE_API_BASE_URL`,
  cookie auth (`withCredentials`), CSRF header on POST/PUT/PATCH/DELETE,
  30 s default timeout (45 s FixBot, 120 s uploads), every failure
  rejected as an `ApiError` (`status`, `code`, `message`, `isTimeout`,
  `isNetworkError`), and 401 → clear session → `/login`.
- `auth.api.js`, `diagnosis.api.js`, `bookings.api.js`, `payments.api.js`,
  `shipments.api.js` for the main flows. Every other page now uses the
  client with relative `/api/...` paths — the backend URL appears in one
  place only. `src/config/axios.js` (global axios mutation) is gone.
- FixBot pages used `fetch` without cookies; they now go through the
  client, so signed-in users are recognised by the backend.

## Shipment / mail-in pickup
- `Shipment.jsx` (public) and `MailIn.jsx` (dashboard) were ~identical;
  both now render `ShipmentWizard.jsx`.
- "City / State" free text → **Pickup area (Abuja)** select, loaded from
  the server with each area's fee (e.g. Garki ₦2,000, Lugbe ₦4,000,
  Kubwa ₦4,500). The fee follows the area through summary and payment.
- Pickup time is now a list of 1-hour windows, 8 AM – 10 PM Abuja time,
  at least 2 hours ahead; past/too-far dates can't be chosen.
- Guests on the public page are asked to log in before paying (the
  backend always required it — previously they'd pay and then fail).
- "Track Shipment" goes to the shipments page instead of an alert.

## Book a call
- Slots come from the same rules as the backend: 8:00 AM – 9:30 PM
  starts, Abuja time, 1 hour's notice. At 9 PM today is disabled and
  only other days can be picked. Slots refresh every minute.
- Steps are now Time → Details → Type → Review & Pay; the booking is
  confirmed automatically after Paystack succeeds. If confirmation fails,
  a "Retry confirmation" button reuses the same payment (no double charge).
- The calendar invite now uses the actual booked time.

## Payments (both flows)
- The server prices and registers the payment first
  (`POST /api/payments/initialize`); Paystack is opened with the server's
  reference and amount. The client no longer decides what it pays.

## FixBot
- Renders three answer types: knowledge base, AI, and the new
  "no match" answer (AI unavailable / limit reached) with book / mail-in
  buttons. Errors (rate limit, validation, timeouts) are shown instead of
  an empty modal.
- Fixed the repair estimate: every number was multiplied by 1,600, so
  "₦8,000" displayed as ₦12,800,000. Naira amounts are now shown as-is.

## Tests (Vitest)
- `src/api/client.test.js`, `src/utils/*.test.js`,
  `BookCall.test.jsx`, `ShipmentWizard.test.jsx`, `Diagnosis.test.jsx`
  plus the existing suites — `npm test`.

# Part 2 — repair lifecycle, notifications, pricing, FixBot

## Customer: My shipments (`/usershipments`)
- Each shipment is a card with a dot timeline of all nine steps, with
  times and notes; the current step pulses.
- **Quote panel** when waiting for approval: diagnosis, repair cost,
  return delivery, total. "Approve and pay" or "Decline" (shows the
  return fee before charging). If confirmation fails after paying, a
  retry reuses the same payment.
- **Delivery panel** when ready for delivery: "I've received my device"
  with a live countdown to automatic confirmation.

## Admin: Shipments (`/adminshipments`)
- The free status dropdown is replaced by buttons for the allowed next
  step only, plus "Send diagnosis & quote" / "Revise quote" (a form for
  the diagnosis and repair cost). Shows when it's waiting on the customer.
- Compact dot progress in the table; full timeline, quote and payment
  details in "Details".

## Notifications
- Clicking a notification opens what it's about (shipment, booking or
  ticket) for customers, technicians and admins.

## Admin: Pricing (`/adminpricing`)
- Edit call prices, pickup areas (with "Recalculate fees from rate
  card", add area, switch off), the rate card, delivery confirmation
  hours, and whether declining costs the return fee.

## FixBot
- New animated FixBot mascot (`src/components/fixbot/`): a robot in a
  Fixer t-shirt with a screwdriver, drawn in SVG. It dances while idle,
  works while thinking, hops when it finds an answer, tilts its head
  when it can't, and stays still for people who prefer reduced motion.
- The homepage FixBot modal: FixBot stands on a blue blueprint panel and
  answers in speech bubbles. The Smart Diagnosis pages (customer and
  admin) use the same mascot and FixBot presents each result.

# Part 3 — technician jobs, call sessions, visual accents

- **Technician → Assigned jobs:** appointments, repairs and other
  tickets together, filterable; **Appointments:** calls by type;
  **Repairs:** mail-in devices with "Mark repaired" / "Can't repair".
  No amount is asked anywhere when completing work.
- **Start session per call type:** remote support → MeshCentral; voice →
  customer's number with Call now / WhatsApp; video → opens the meeting
  link (customer sees the same link after booking and on the appointment page).
- **Admin shipments:** "Assign technician & start repair"; shows when
  it's waiting for the technician.
- **Articles/videos:** TinyMCE removed from videos too (and the package);
  admin pages load drafts via the admin endpoints; public pages show
  published only (admins still get a preview). Plain-text content is
  shown with paragraphs and line breaks; old TinyMCE HTML still works.
- **Fixed** the broken comment in `ArticleForm.css`.
- **Look:** circuit-board traces with a moving cyan signal on the
  dashboard banners and around the home hero photo, blueprint dot grids,
  circuit corners on stat cards and the sidebars, a trace marker under
  page titles, generated circuit covers for articles without an image,
  and a reading-progress bar on articles.
